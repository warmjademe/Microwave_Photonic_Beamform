# 共同训练模型包的实际在线耗时

最终各方法在同一训练群组拟合后，计时必须使用这一批权重。`benchmark_bundle_online.py`将已核验的模型包作为原`OnlineController`的产物根目录；输入案例、网络前向、估计与搜索、测量反馈重放、线程、计时次数和资源门限均复用冻结的`benchmark_online.py`。不编辑原计时器，不读预测缓存。

入口只有两种模式：`--preflight`固定原864环境模型包、旧测试索引0的4/12/20 GHz与六种代表方法；`--freeze PATH`读取正式方案冻结文件，使用其中共同训练权重和全部37种普通在线方法。正式计时仍固定旧测试集六个功率组各自第一个环境、全部17载频，不为计时提前生成新确认信号。教师与数字MRC的硬件/信息条件不同，不加入普通光子控制时间排名。

每个案例实际计算一次反馈轨迹，热身两次，再真实计算三次计时与一次分段诊断。仅反馈标量可以按完全一致的控制查询顺序重放；输入处理、CPU/GPU传输、网络前向、搜索与档位量化仍每次执行。软件时间排除反馈仿真回调，标称测量与切换时间另列；这些估计值不是实体器件时间测量。

计时输出的`binding.json`先绑定共同训练成员、模型包清单SHA、来源快照及正式冻结身份。原计时结果位于子目录`timing`。独立审计检查所有实际加载的权重与统计参数都来自绑定包，再调用原计时审计器重算各方法平均、中位、95百分位和测量开销；演练还逐控制码与已核验旧案例比较。

正式模式强制启用原`final-idle`资源门限，存在其他GPU进程、项目数值进程或CPU背景忙碌超过60%时停止并保存现场。演练期间可以存在后台实验，因此演练耗时不得用于最终速度排名。每个运行使用新输出目录，不覆盖失败记录。

华硕项目`source_codes`目录下的演练命令：

```sh
../.venv_dl/bin/python -u study_full_baselines/benchmark_bundle_online.py \
  --project .. --output ../dataset_simulation/diagnostics/20260926_bundle_timing_preflight \
  --preflight
```

全部规模、共同训练、最终方法冻结完成且其他数值任务释放资源后，使用同一入口的`--freeze`模式。每次计时不增加训练随机种子。演练完成仅证明新权重入口和计时链条可用，不代表正式计时或完整研究已完成。
