# A/F 在线软件成本分解

2026-10-30。只测量冻结控制器的计算成本，不修改模型或控制策略。

- 从既有 864 测试环境的六个功率层分别取编号最小者，覆盖全部 17 个载频，共 102 条输入。选择不读取接收质量。预检只使用测试索引 0 的 4/12/20 GHz，不进入正式时间统计。
- 比较 A 直接输出、A+F、传统估计+F 和固定扫描；共同使用原 RQ2 运行包与公开输入。原始反馈轨迹只由核查回调持有；控制器仍实际生成候选，只有查询次序、完整控制码一致时才返回对应的原导频分数。最终控制与全部轨迹必须一致。
- 每条输入先热身两次，然后无探针计时三次；另执行三次带探针分段诊断，二者分开报告。单输入、单 CPU 线程、原 GPU/精度设置，模型加载另记，不进入在线成本。
- 分段记录：初始反演与完整响应估计、GPU 网络前向、离散求解、其他控制逻辑。网络前向是响应估计的子项，不重复求和；GPU 输入输出拷贝计入响应估计的其他成本。反馈管理包括候选去重、码本遍历、分数比较等，排除验证回调本身。
- 无探针总时间用于软件总体成本。分段诊断有同步和包装开销，仅解释各部分成本，不用它替代无探针时间。保存逐次值，报告均值、中位数及第 95 百分位。
- 正式执行前、每个方法前后，核对 GPU 无其他计算进程、本项目无其他数值任务，且 5 秒 CPU 采样忙碌率不超过 60%。不停止其他服务；门限失败保留失败尝试，不拼接竞争条件下的时间。预检可在有其他任务时执行，但明确不是正式时间结果。
- 硬件成本是独立的假设估算：每次探测使用两块导频，采集时长按实际模拟帧参数计算为 1.24 微秒；每次切换按配置假设 1 微秒。预算包括初始测量，输出控制另计一次切换；总估算为 B×(1.24+1)+1 微秒，16/64 次分别为 36.84/144.36 微秒。该值不含真实设备通信、稳定等待或额外校准，不能当作硬件实测。
- 所有原始反馈与源码哈希在开始、结束核验。预检通过后才可正式运行；正式任务等待已有 H/R/C 评价与统计完成并满足资源门限。
